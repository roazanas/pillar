# Реализация дорожной карты Pillar

Реализованное дерево развивается как `2.0.0-alpha.1`: синтаксис несовместим с
первоначальной 1.x, а публичный стабильный релиз требует прохождения всей CI-матрицы.
Исторические находки исходной ревизии сохранены в LANGUAGE_AUDIT.md; актуальные
правила описаны в LANGUAGE.md, переход — в MIGRATION.md.

| Этап | Реализация | Проверка |
| --- | --- | --- |
| Библиотечное ядро | Анализ возвращает данные и диагностики; CLI отделён | Постоянные интеграционные тесты |
| Позиции | Физические сегменты, UTF-8, CRLF, виртуальные пробелы, UTF-16 LSP | Проверки вертикальных имён и координат |
| Парсер и control flow | Полный EL, min-int, приоритеты, завершение блоков, недостижимость | Включая RET в циклах и бесконечные циклы |
| Семантика | Типы, области видимости, сигнатуры, проверенное представление | Forward calls, рекурсия, float/bool, compile-fail случаи |
| Генерация | Native Cranelift, проверяемая арифметика и источники runtime-ошибок | Обычный и оптимизированный режимы |
| Runtime и переносимость | Встроенный целевой архив, int64_t, MSVC/Unix, атомарный output | macOS ARM64 локально; пять нативных jobs в CI |
| CLI и форматтер | Все запланированные команды, JSON, legacy aliases | Реальные subprocess-тесты и идемпотентность |
| Библиотека | Строки, Unicode, преобразования, ввод-вывод, math/env/fs | Программы и тесты ошибок выполнения |
| Модули | Относительные импорты, alias, PUB, запрет циклов | Межфайловый запуск, видимость и циклы |
| Коллекции | Массивы, структуры, автоматическое RC и copy-on-write | Вложенные изменения, cleanup, ASan/UBSan |
| Документация и поставка | Справочник, миграция, MIT, воспроизводимые архивы | Извлечённый compiler проверяется в чистой папке |
| Редакторские инструменты | Stdio LSP, VS Code-расширение, column operations, preview | Протокольные тесты и JS-тесты сетки |
| Playground | Два вида, операции со столбцами, loopback API, Docker limits | HTTP/границы запросов локально; реальный Docker smoke — CI |

## Границы подтверждённой готовности

- Локально прошли 35 Rust-тестов, Clippy с запретом предупреждений, 10 000
  воспроизводимых мутаций frontend (1 523 корректных программы также проверили
  идемпотентность форматтера), четыре ASan/UBSan-сценария, четыре JS-теста и пять
  HTTP/constraint-тестов. Проверена арифметика в release-сборке компилятора.
- Нативный архив извлекается в чистую папку с пробелами; проверяются хеши всех
  файлов и реальный запуск пяти исходных примеров. Собран локальный VSIX.
  Playground проверен в браузере при ширине 320 и 1280 пикселей, включая Tab.
- Начальный benchmark macOS ARM64 сохранён в benchmark-macos-arm64.json;
  измерения включают запуск процессов, а RSS — накопленный максимум дочерних
  процессов, поэтому эти числа нельзя считать профилем отдельных этапов.
- Локальная машина — macOS ARM64. Остальные ОС и архитектуры нельзя считать
  проверенными до фактического успешного запуска соответствующих CI jobs.
- В локальном окружении Docker-клиент есть, но движок не запущен. Изоляция контейнера
  реализована и вынесена в реальные CI smoke tests; локально проверены HTTP API,
  команды ограничений и отказ от выполнения в preview-only режиме.
- VS Code-расширение проверяется на синтаксис и операции сетки. Нужен smoke test
  в самом Extension Development Host перед его распространением.
- Никакой релиз, marketplace-пакет или публичный playground не опубликован.
- LSP rename охватывает текущий модуль и достижимые импорты, не индексирует
  неоткрытые обратные зависимости всего workspace и консервативно запрещает
  потенциальный захват существующего имени.
- Текущий fuzz runner выполняет воспроизводимые мутации. Длительные кампании
  coverage-guided fuzzing остаются дальнейшим усилением проверок.

## Следующий цикл после прохождения проверок

1. Зафиксировать результаты нативной CI-матрицы и исправить найденные платформенные
   различия; подтвердить VS Code и реальное контейнерное выполнение.
2. Накопить воспроизводимые benchmark-базисы, затем улучшать повторное использование
   данных, временных значений и буферов по измерениям.
3. Усилить fuzzing и корпус regression cases; развить восстановление парсера и
   выдачу нескольких независимых диагностик за один проход.
4. Добавить workspace-индекс LSP и расширить проверки Unicode/IME и screen reader
   в редакторах. Стабилизировать редакторский интерфейс перед публикацией.
5. Исследовательский резерв: generics, алгебраические типы, FFI, менеджер пакетов,
   async/параллельность и дополнительные backend — только с отдельным предложением
   и программой, показывающей необходимость.
